01

foundations

Hoard is a collector's terminal. The visual system mirrors a librarian's worktable — graph-paper voids, hairline rules, archival labels, the occasional thermal-receipt. Build with restraint: dark backgrounds, mono type, single-pixel borders. Color is reserved for status and emphasis.

color & status

Two neutral families and four accent ramps. Each accent has one job. Don't reach for amber to mean "playing" — use green. Don't reach for red to mean "wishlist heat" — use amber. Status colors are a contract; charts and emphasis are derived from those contracts.

// the status contract — single source of truth
status color token sigil usage
Playing #5FC26A --green [●] active engagement. dot in sidebar, meter fill, "now playing" card border.
Backlog #6B6F72 --paper-faint [ ] default / idle. no accent color. backlog is the absence of action — neutral grey.
Completed #ECE8DE --paper [x] finished. uses primary paper white — the brightest neutral, not an accent. completion is achievement, not status.
On Hold #69A1D4 --blue [~] paused. cool, calm — distinguishable from active.
Dropped #E2553A --red [/] abandoned. the only status with red.
Wishlist #D4A017 --amber [?] aspirational. star icon ⭑ + amber border. diamond shape on dot variants.
Rule
A status's color is its identity. When showing a stat about a status (e.g. "286 in Backlog · 66.8%"), use that status's color — not whatever feels visually nice. The Backlog tile in the dashboard should not be amber just because backlogs feel "warning-y" — backlog is grey, period. Use amber only on the delta ("+3 this week") or the wishlist count.

04

components

Every component is built from hairline + uppercase mono + tabular numerals. Variants exist for the four status accents — but the structure never changes. A green button is a default button with a green ring. Don't fork.

chip

tag · status · filter
all on hover ● playing ★ wishlist / dropped ~ on hold PRIMARY FEATURED
24px tall, 10px caps, 1px border. tone variants tint border + color; solid swaps to --paper bg.
  • filter chips → unfilled (.h-chip)
  • active filter → .on (white border)
  • status badge → tone matches the status table

button

action
30px (sm 24px). uppercase 11px / .1em letter-spacing.
  • primary for the single most important action on a screen — never two on the same view
  • amber/green for status-tinted side actions (e.g. wishlist)
  • danger for destructive: drop, delete, reset

panel

surface
.panel — flat ink card
.panel.raised — ink-2 (selected/footer)
.panel + dashed border — note & placeholder
1px hairline. no shadow. nest panels by varying the fill (--ink → --ink-2), never by adding a second border.

06

audit · current build

Inconsistencies found in Hoard.html rev 0.7. Each is mapped to a rule above. Listed by severity. Walk through these in order; fix the contracts before the cosmetics.

// findings
SEVHIGHSTATUS CONTRACT

Backlog tile rendered amber on the dashboard

the BACKLOG · 286 · 66.8% stat tile uses tone='amber'. amber is the wishlist accent. backlog is grey (paper-faint), per the status table. mixing them blurs the contract — users can't tell whether amber means "to play" or "to buy".

FIX

switch the tile's tone to null (paper). move amber to the wishlist tile only. emphasis on backlog volume → use a 2px --paper top-border, not a color shift.

SEVHIGHSTATUS CONTRACT

Detail-screen status chip painted with star + amber when status is Backlog

on the receipt detail, the status pill renders ★ backlog with tone="amber". backlog isn't wishlist. the star and the amber both belong to wishlist alone. when the game's actual status is backlog, it should read with a grey dot.

FIX

read the chip's tone from the status table — drive it from one map. statusToChip(s) → { dot, tone, icon }. never hard-code the icon at the call site.

SEVMEDSEMANTIC COLOR

Completion percentage rendered green

12.1% completed appears in green on the dashboard hero. completion's color is --paper (per the status table). green belongs to active playing.

FIX

set the number to --paper; keep the green only for the $ prompt prefix that opens the line.

SEVMEDTYPE

Dollar amounts inconsistently mono'd

"$3,420" on the hero uses Plex digits; "$3.4k" in the stat grid uses JBM tnum. different surfaces, same number, two voices.

FIX

any number that participates in a stat is JBM + tnum. prose-embedded numbers stay in Plex. wrap currency in <span class="t-mono t-tnum"> when it's a stat.

SEVLOWSPACING

Cell heights drift across stat grids

the original 4-up grid let one wrapping label push its number down 6px. fixed in the HLTB grid; replicate the 24/32/14 row template across every stat grid (dashboard, receipt, library shelf headers).

FIX

extract a shared <StatTile> component using the row template. all numeric grids should mount it.

SEVLOWRULE USE

Mixed dotted/dashed/solid rules without rhythm

some sections separate with solid hairlines, some with dotted. the rule above (rules & dividers) defines a hierarchy: solid for default, dot for soft, dash for major regions, double for receipt edges. apply consistently per-screen.

FIX

pick one divider style per region tier and stick to it. dashboard top-level → dash, intra-card → solid.

07

do · don't

do

  • treat status colors as a contract — one accent per status, everywhere
  • let hairlines do the work; resist adding shadows or fills
  • set numbers in JetBrains Mono with tabular figures
  • use --ink for surfaces and --ink-2 only for raised/selected
  • open every section with a // lowercase marker
  • reserve the receipt motif for the detail screen

don't

  • tint stats in amber to mean "warning" — that's red's job
  • stack green + amber + red in one chart legend; pick the dominant story
  • introduce gradients, drop-shadows, or rounded corners > 0
  • mix Inter / Roboto / system-ui — only JBM, Plex, Major Mono
  • use icons where a sigil [●] or chip would do
  • write Title Case in UI labels — Hoard speaks lowercase
